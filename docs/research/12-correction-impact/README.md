# 정정 공시가 재무 숫자를 얼마나 바꾸나 (2026-09-28, 표본 86건)

## 3줄 요약
- 봇은 정정된 보고서를 **원본 접수일**에 넣되 숫자는 **정정본**에서 가져온다(운영자 결정 2026-09-28). 그런 원본이 4,172건(전체 공시 40,689건의 10%)이다. 원본 문서를 직접 읽어 비교한 결과, **매출·영업이익은 한 건도 바뀌지 않았고**(각 0/38, 0/39), **순이익은 4/35(11%), 자본총계는 8/60(13%)** 이 0.5% 넘게 달랐다.
- 바뀐 건은 모두 원본→정정 간격이 **90일을 넘는** 경우였다. 0~90일(정정 원본의 58%)에서는 71개 비교 중 자본 3건(작은 차이)뿐이고 손익은 0건이었다. 91일 이상에서는 순이익이 20건 중 4건 바뀌었고 한 건은 부호까지 바뀌어 ROE 백분위가 64칸 움직였다.
- **권고: 간격 90일 이하만 원본 날짜에 정정 숫자를 쓰고, 90일을 넘는 정정은 정정본 접수일부터 쓴다.** 영향 범위는 정정 원본의 약 42%(≈1,740건)이고, 미래 정보가 섞이는 순이익 행은 전체 공시의 약 1%에서 사실상 0으로 줄어든다.

| 항목 | 내용 |

| 파싱 규칙 | `scripts/parse_compare.py` 머리말. 목차 "요약재무정보" 절의 표에서 행 이름으로 항목을 고르고 당기(첫 숫자 칸) 값을 쓴다. 단위(원·천원·백만원·억원)를 못 찾거나 연결/별도 표를 못 가리면 **실패로 센다** |

### 지표 영향 (`impact_roe.csv`)
숫자가 바뀐 8건을 같은 기간 봇 DB 전 종목(2,400~3,300종목) ROE 분포에 넣어 보면 백분위 이동의 중앙값은 1.3칸이다. 그러나 91일 넘는 두 건이 크다.
- 2024년 사업보고서, 간격 91~365일: 원본 순이익 +59억 → 정정 −56억. ROE 백분위 85.5 → 21.3 (**−64칸**)
- 2025년 1분기, 간격 91~365일: ROE 백분위 95.1 → 71.4 (−24칸)

EP도 같은 순이익으로 움직인다. 매출·영업이익은 바뀐 적이 없으므로 SP·OPG·OPG_Q는 영향이 없다. 바뀐 쪽은 대체로 정정이 **숫자를 나쁘게** 바꿨다. 과거 재현에서 이 정보를 원본 날짜에 쓰면 나쁜 종목을 미리 피하는 셈이라 성적이 조금 좋게 나온다.

## 판정과 권고
- 정정본 숫자를 원본 날짜에 쓰는 것은 **매출·영업이익에는 미래 정보를 섞지 않는다**(표본에서 0건. 0/77이므로 참 비율은 95% 신뢰로 4% 미만).
- **순이익·자본에는 섞는다.** 다만 거의 전부 간격이 90일을 넘는 정정(재작성·감사 뒤 수정)에서 생긴다. 0~90일 정정은 대부분 기재·첨부 정정이다.
- **권고 규칙:** 원본→정정 간격이 90일 이하이면 지금처럼 원본 날짜에 정정 숫자를 쓴다. 90일을 넘으면 원본은 넣지 않고 정정본 접수일부터 쓴다. 정정 원본의 58%는 지금처럼 빨리 들어오고, 미래 정보 위험이 있는 42%만 늦춘다. 이 규칙은 아직 코드에 넣지 않았다(운영자 결정 필요).

## 따로 발견한 것
- **결산월이 12월이 아닌 회사의 기간이 틀린다.** 봇은 보고서 종류로 기간을 정한다(사업보고서=12월 31일, 반기=6월 30일 …). 예: "사업보고서 (2022.09)"(9월 결산)가 2022-12-31 연간으로, "반기보고서 (2022.12)"가 2022-06-30으로 저장됐다. 표본 86건 중 4건이 이 경우였다. 정정 문제와 별개인 수집 버그다.
