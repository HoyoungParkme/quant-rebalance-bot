# 구현 계획

## 0. 이 문서가 다루는 것

구현을 슬라이스로 나누고 순서를 정한다. 슬라이스 하나는 하나의 브랜치, 하나의 PR이다. `완료` 행에 커밋을 기록한다.

순서의 원칙은 셋이다. 검증 코드와 같은 결과가 나오는 것을 먼저 확인한다. 실제 돈이 걸리는 부분은 마지막이다. 증권사 키 없이 할 수 있는 일을 앞에 둔다.

**작업 순서 규칙(2026-09-29부터 엄수):** 코드를 바꾸기 전에 해당 명세(PRD → SCN → UC → SEQ → MS → DOM-003)를 먼저 고친다. 급한 버그도 같은 날 안에 명세에 적는다. 9/23~29에는 코드부터 고치고 명세를 뒤따라 적은 일이 여러 번 있었고, 그 되먹임은 9/29에 전부 반영했다(PRD v5, SCN v3, UC v2, INFRA v5, DOM-003 v4, SEQ v2, MS v3, API v4).

2026-09-29 기준 A~F 전 슬라이스의 코드가 있고, 봇이 모의 모드로 상주 가동 중이며 **첫 모의 매수(10종목 + 지수 ETF)가 9/29에 나갔다.** 남은 코드는 슬라이스 G(손절)다.
