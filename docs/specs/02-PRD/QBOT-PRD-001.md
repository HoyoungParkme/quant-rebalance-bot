# PRD — 제품 요구

## 1. 목표

이 제품은 과거 데이터로 검증한 종목 선정 규칙을 매달 같은 방식으로 실행하는 개인용 자동 매매 봇이다. 사용자는 고객 본인 한 명이다.

#### G1 검증된 규칙을 사람 손 없이 매달 똑같이 실행한다

#### G2 운영비를 전기요금 수준으로 유지한다

#### G3 실제 돈을 넣기 전에 모의 운용으로 봇의 동작을 확인한다

#### G4 실제 돈에서 미리 정한 한도를 넘는 손실이 나지 않게 한다

#### G5 같은 중소형주 평균보다 나은 수익을 낸다

## 2. 비목표

| 비목표 | 이유 |
|---|---|
| 코스피 지수보다 높은 수익 | 100만원 모의 운용에서 전략 +42.9%, 코스피 +184.9%였다. 검증이 뒷받침하는 것은 "같은 중소형주 안에서 고르는 것보다 낫다"까지다 |
| 분·초 단위 매매 | 개인은 증권사 API 지연 때문에 속도로 경쟁할 수 없다. 거래세 때문에 잦은 매매는 구조적으로 불리하다 |
| 호재 공시·뉴스를 보고 매수 | 공급계약 공시 다음 날 시가 매수의 5일 승률이 39%였다 |
| 외국인·기관 수급, 거래량 급증 추격 | 수급 추종 연 -5.5%, 거래량 급증 추격 연 -23.1%였다 |
| 외부 요인으로 다음 달 예측 | 미국 증시·환율·변동성지수는 같은 달에만 같이 움직이고 다음 달 상관은 0에 가까웠다 |
| 언어모델이나 분류 모델이 매수·매도를 결정 | 출력이 매번 달라지면 과거 검증이 무효가 된다. 머신러닝 비교 실험에서도 상위 20종목 수익이 단순 규칙보다 낮았다 |
| 다른 사람에게 신호 제공이나 자금 운용 | 유사투자자문·투자일임 규제 대상이다 |
| 해외 주식, 코인, 공매도, 레버리지 | 검증하지 않았다 |
| 웹 화면 | 알림과 기록 파일로 운영한다. 화면은 만들지 않는다 |
| 실적 공개일 기준 수시 교체 | 2026-09-23 검증(`docs/research/06-daily-signals`): 지표 7개를 합친 점수에서는 수익 개선이 연 0.1~0.9%p에 그치고 매매가 16~22% 늘어 비용이 그만큼 더 나갔다. 손실폭도 줄지 않았다 |

## 3. 요구사항

### 3.1 기능

#### R1 시세 수집

근거: [[QBOT-RFQ-001#Q3]]

매 거래일 장 마감 후 코스피·코스닥 전 종목의 일봉(시가, 고가, 저가, 종가, 거래량)을 받아 저장한다. 거래정지 여부도 함께 저장한다.

- [ ] 거래일마다 전 종목 일봉이 저장된다
- [ ] 수집이 실패하면 알림이 가고, 다음 실행에서 빠진 날짜를 채운다
- [ ] 상장폐지된 종목의 과거 시세를 지우지 않는다

#### R2 재무 수집과 공개 시점 기록

근거: [[QBOT-RFQ-001#Q6]], [[QBOT-RFQ-001#Q11]]

전자공시에서 연간·분기 재무와 잠정실적을 받아 저장한다. 각 수치에는 그 공시의 접수 일자를 함께 저장한다. 전자공시 API는 접수 시각 없이 일자만 준다. 검증에서 같은 영업이익 성장 지표라도 연 1회 갱신은 월 +1.24%, 분기 갱신은 +1.63%, 공개 후 30일 이내 정보만 쓰면 +2.18%였다.

- [ ] 모든 재무 수치에 공시 접수 일자와 공시 번호가 붙어 있다
- [ ] 정정 공시가 나오면 원래 값을 덮어쓰지 않고 새 행으로 추가한다
- [ ] 매출, 영업이익, 순이익, 자본, 주식 수를 저장한다

#### R3 시점 고정 조회

근거: [[QBOT-RFQ-001#Q6]]

지표를 계산할 때는 "판단 시점까지 공개된 데이터"만 읽는다. 이것을 사람의 주의가 아니라 조회 함수가 강제한다. 모든 데이터 조회는 기준일을 인자로 받는다. 시세는 거래일이 기준일 이하인 행만, 재무는 접수 일자가 기준일보다 앞선 행만 돌려준다. 접수 시각을 알 수 없으므로 기준일 당일에 접수된 공시는 쓰지 않는다. 월 1회 판단에서 하루 늦는 것은 문제가 되지 않는다.

- [ ] 기준일 없이 재무·시세를 읽는 경로가 코드에 없다
- [ ] 기준일 당일 또는 그 뒤에 접수된 공시를 읽으려 하면 테스트가 실패한다
- [ ] 과거 날짜를 기준으로 다시 돌리면 그날 실제로 나온 것과 같은 종목 목록이 나온다

#### R4 종목 점수와 선정

근거: [[QBOT-RFQ-001#Q3]], [[QBOT-RFQ-001#Q5]], [[QBOT-RFQ-001#Q10]]

대상 종목마다 지표 7개를 계산하고, 지표별로 전 종목 순위를 백분위로 바꿔 더한다. 점수 상위부터 보유 종목 수만큼 고른다. 계산은 나눗셈, 표준편차, 순위뿐이다. 같은 입력이면 항상 같은 결과가 나온다.

| 구분 | 지표 | 방향 |
|---|---|---|
| 재무 | 순이익 ÷ 시가총액 | 높을수록 |
| 재무 | 매출 ÷ 시가총액 | 높을수록 |
| 재무 | 자기자본이익률 | 높을수록 |
| 재무 | 영업이익 성장률 (연간) | 높을수록 |
| 재무 | 영업이익 성장률 (최근 분기, 전년 같은 분기 대비) | 높을수록 |
| 위험 | 60일 변동성 | 낮을수록 |
| 위험 | 20일 회전율 | 낮을수록 |

대상은 보통주이고, 주가 1,000원 이상, 20일 평균 거래대금 5억 이상, 시가총액 500억 이상, 판단일에 거래된 종목이다. 소형주를 포함한다. 1주 가격이 종목당 예산을 넘는 종목은 건너뛴다. 보유 종목 수는 10이다.

이 7개는 2024년 12월까지의 데이터에서 월 수익차의 t값 절대값이 2.0 이상이었던 지표다. 같은 기준에서 자본 ÷ 시가총액, 12개월 상승률, 3개월 상승률, 52주 고가 근접, 거래량 급증은 기각됐다.

- [ ] 지표 목록, 방향, 대상 필터, 보유 종목 수가 설정 파일 하나에 있다
- [ ] 검증에 쓴 모의 운용 코드와 같은 날짜·같은 데이터로 돌렸을 때 선정 종목이 100% 일치한다
- [ ] 선정 과정에 난수, 외부 모델 호출, 현재 시각 의존이 없다

#### R5 월 1회 교체

근거: [[QBOT-RFQ-001#Q5]], [[QBOT-RFQ-001#Q8]]

매월 마지막 거래일 장 마감 후에 점수를 계산하고 목표 종목을 정한다. 주문은 다음 거래일에 낸다. 목표에 남아 있는 보유 종목은 건드리지 않는다.

하락장 현금 전환 규칙을 **켠다**(2026-09-23부터). 코스피 월말 종가가 최근 10개월 평균 이하이면 그달의 종목 부분을 전부 현금으로 둔다. 지수 상장지수펀드 부분(R14)은 그대로 둔다 — 검증의 지수 혼합 결과가 이 조건에서 나왔다. 지수 월말 종가가 10개월치가 안 되면 짧은 평균으로 판단하지 않고 판단을 거부한다.

- [ ] 월말 판단과 다음 거래일 주문이 사람 개입 없이 실행된다
- [ ] 목표에서 빠진 종목만 팔고, 빈 자리만 새로 산다
- [ ] 판단 결과(점수 상위 60개와 선정 종목)가 주문 전에 저장되고 알림으로 간다
- [ ] 현금 전환이 걸린 달은 알림에 그 사실이 표시된다

#### R6 주문 실행

근거: [[QBOT-RFQ-001#Q12]]

매도를 먼저 내고, 매도 대금이 들어온 뒤 매수를 낸다. 주식은 정수 단위로만 산다. 종목당 예산은 평가액을 보유 종목 수로 나눈 값이다.

- [ ] 거래정지 종목은 주문하지 않고, 거래가 재개되는 날까지 매일 다시 시도한다
- [ ] 미체결 주문은 정해진 횟수만큼 가격을 고쳐 다시 낸다. 그래도 안 되면 알림을 보내고 멈춘다
- [ ] 같은 판단에 대해 주문이 두 번 나가지 않는다. 봇이 주문 도중 죽었다 살아나도 마찬가지다
- [ ] 현금이 부족하면 점수 순서대로 살 수 있는 만큼만 산다

#### R7 모의와 실전이 같은 코드

근거: [[QBOT-RFQ-001#Q13]]

모의 계좌와 실전 계좌는 설정값 하나로 바뀐다. 종목 선정, 주문 생성, 기록 코드는 둘이 같다. 다른 것은 증권사 접속 주소와 계좌 정보뿐이다.

- [ ] 모의와 실전을 가르는 분기가 증권사 접속 설정 밖에는 없다
- [ ] 현재 모드가 모든 알림과 기록에 표시된다
- [ ] 실전 모드는 R8의 관문을 통과하기 전에는 켜지지 않는다

#### R8 실전 전환 관문

근거: [[QBOT-RFQ-001#Q13]]

모의 운용에서 아래 조건을 모두 채우고, 사용자가 직접 승인해야 실전으로 넘어간다.

| 조건 | 기준 |
|---|---|
| 모의 운용 기간 | 3개월 이상, 월말 교체 3회 이상 |
| 주문 오류 | 0건 |
| 선정 일치율 | 검증 코드와 100% |
| 월 수익 차이 | 같은 기간 모의 계산값과 1%p 이내 |
| 실전 첫 달 투입 | 정한 자금의 30%. 첫 달 체결 오차가 1%p 이내면 나머지 투입 |

- [ ] 모의 운용 기간, 주문 오류 건수, 선정 일치율, 수익 차이를 봇이 집계해 보고한다
- [ ] 조건을 채우지 못하면 실전 모드 설정이 거부된다
- [ ] 조건을 채워도 자동으로 넘어가지 않는다. 사용자가 승인 명령을 내려야 한다
- [ ] 실전 첫 달은 정한 자금의 30%만 넣는다

#### R9 손실 한도와 비상 정지

근거: [[QBOT-RFQ-001#Q13]]

계좌 평가액이 고점 대비 30% 내려가면 봇이 새 매수를 멈추고 사용자의 결정을 기다린다. 100만원 모의 운용의 최대 손실폭은 -25.2%, 가장 나쁜 달은 -9.7%였다. 한 종목의 비중 상한은 평가액의 15%, 하루 주문 총액 상한은 평가액의 2배(매도와 매수 합)다. 사용자가 재개하면 고점을 그 시점의 평가액으로 다시 잡는다. 다시 잡지 않으면 재개 직후 또 한도에 걸리기 때문이다. 대신 처음 투입한 원금 대비 누적 손실은 따로 기록해 보고에 표시한다.

- [ ] 고점 대비 손실이 30%에 닿으면 새 매수가 멈추고 알림이 간다. 보유 종목을 자동으로 팔지는 않는다
- [ ] 한 종목이 평가액의 15%를 넘게 되는 매수는 거부된다
- [ ] 하루 주문 총액이 평가액의 2배를 넘으면 거부된다
- [ ] 사용자가 알림 채널에서 명령 하나로 봇을 멈출 수 있다
- [ ] 멈춘 상태는 봇을 다시 시작해도 유지된다
- [ ] 재개 시 고점이 재설정되고, 원금 대비 누적 손실은 계속 기록된다

#### R10 기록과 계좌 대조

근거: [[QBOT-RFQ-001#Q8]], [[QBOT-RFQ-001#Q12]]

판단, 주문, 체결, 일별 평가액을 모두 저장한다. 매일 봇의 기록과 증권사 계좌의 잔고를 맞춰 본다.

- [ ] 매매마다 종목, 수량, 가격, 수수료, 세금, 손익이 남는다
- [ ] 봇의 보유 기록과 계좌 잔고가 다르면 알림이 가고 새 주문이 멈춘다
- [ ] 기록만으로 월별 평가액과 매매 내역 표를 다시 만들 수 있다

#### R11 알림

근거: [[QBOT-RFQ-001#Q1]]

사용자는 봇을 들여다보지 않아도 상태를 안다.

- [ ] 주문, 체결, 오류, 한도 도달이 메신저로 온다
- [ ] 거래일마다 일일 요약(평가액, 전일 대비, 보유 종목)이 온다
- [ ] 봇이 살아 있다는 신호가 일정 간격으로 온다. 신호가 끊기면 사용자가 알 수 있다

#### R12 성과 보고

근거: [[QBOT-RFQ-001#Q8]], [[QBOT-RFQ-001#Q11]]

매월 수익을 세 기준과 비교한다. 코스피, 전 종목 동일 비중, 같은 기간 같은 규칙의 모의 계산값이다.

- [ ] 월별 수익률, 고점 대비 손실, 원금 대비 누적 손익, 누적 비용이 보고된다
- [ ] 실제 수익과 모의 계산값의 차이가 보고된다. 이 차이가 체결 오차다
- [ ] 지표 7개 각각의 최근 12개월 효과가 보고된다

#### R13 연 1회 규칙 재점검

근거: [[QBOT-RFQ-001#Q10]], [[QBOT-RFQ-001#Q11]]

매년 1월에 그때까지의 데이터로 후보 지표의 효과를 다시 계산하고, 채택 기준(t값 절대값 2.0 이상)을 통과하는 지표 목록을 보고한다. 규칙 변경은 자동으로 하지 않는다. 검증에서 매년 재선정한 목록은 2025년부터 같은 7개로 안정됐다.

- [ ] 재점검 결과가 현재 목록과 다르면 무엇이 빠지고 들어오는지 보고된다
- [ ] 사용자가 승인해야 설정이 바뀐다
- [ ] 바뀐 설정과 바뀐 날짜가 기록에 남는다

#### R14 지수 상장지수펀드 고정 비중

근거: [[QBOT-RFQ-001#Q9]]

자금의 20%를 코스피200 상장지수펀드로 들고 있는다. 검증에서 전략과 지수의 월 수익률 상관은 0.25였고, 전략 80 대 지수 20에서 손실폭이 -18.5%로 가장 작았다. 비중은 설정값이고 0이면 꺼진다.

- [ ] 지수 비중을 설정값으로 줄 수 있다. 기본값 20%. 0이면 이 기능은 꺼진다
- [ ] 지수 부분은 월말 교체 때 목표 비중에서 5%p 넘게 벗어났을 때만 맞춘다
- [ ] 성과 보고에서 전략 부분과 지수 부분이 따로 보인다

#### R15 위험 종목 제외

근거: [[QBOT-RFQ-001#Q10]], [[QBOT-RFQ-001#Q11]]

관리종목, 투자경고·위험 종목, 거래정지 종목은 매수 후보에서 뺀다. 보유 중인 종목이 관리종목으로 지정되면 다음 거래일에 판다. 검증에서 부실로 상장폐지된 종목의 68%가 점수 최하위 20%에 있었지만 2%는 최상위 20%에 있었다. 감사의견 거절, 횡령·배임, 거래정지 예고 같은 돌발 공시는 제목 키워드 규칙으로 잡아 알림만 보낸다. 분류 모델은 쓰지 않는다.

- [ ] 증권사 API나 거래소 공시로 확인되는 지정 종목이 후보에서 빠진다
- [ ] 보유 종목이 관리종목으로 지정되면 알림이 가고 다음 거래일에 매도 주문이 나간다
- [ ] 보유 종목에 돌발 공시 키워드가 걸리면 알림이 간다. 자동 매도는 하지 않는다
