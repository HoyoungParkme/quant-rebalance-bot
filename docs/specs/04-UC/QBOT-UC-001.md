# USECASE (Cockburn)

## 0. 이 문서의 형식

유스케이스마다 12행 표, 기본 흐름, 확장을 적는다. 확장 번호는 기본 흐름의 몇 번 단계에서 갈라지는지를 뜻한다. `3a`는 3번 단계의 첫 번째 갈래다.

| 접두 | 뜻 | 누가 시작하나 |
|---|---|---|
| UC-A | 자동 | 봇이 시간이나 상태에 따라 스스로 시작한다 |
| UC-H | 사람 | 운영자가 명령으로 시작한다 |
| UC-S | 하위기능 | 다른 유스케이스가 포함해서 쓴다. 혼자 시작되지 않는다 |

"범위"는 모두 봇 프로그램 하나다. "패키지"는 뒤의 도메인 문서에서 도메인 경계의 후보가 된다.

## 1. 액터

| 액터 | 종류 | 설명 |
|---|---|---|
| 운영자 | 주 | 봇을 만들고 자기 돈을 넣은 사람. [[QBOT-SCN-001#P1]] |
| 스케줄러 | 주 | 정해진 시각에 봇을 깨우는 시계. [[QBOT-SCN-001#P2]]가 스스로 움직이는 계기다 |
| 증권사 | 보조 | 주문, 체결, 잔고, 종목 지정 상태를 주는 API. 모의와 실전 두 접속이 있다 |
| 시세 제공처 | 보조 | 전 종목 일봉을 주는 곳 |
| 전자공시 | 보조 | 재무 공시와 접수 일시를 주는 API |
| 메신저 | 보조 | 알림을 전하고 운영자의 명령을 받는 통로 |

## 2. 사용자 목표 수준 유스케이스

#### UC-A1 거래일 저녁 수집과 점검

| 항목 | 내용 |
|---|---|
| 범위 | 봇 |
| 수준 | 사용자 목표 |
| 주 액터 | 스케줄러 |
| 이해관계자와 관심사 | 운영자: 오늘 상태를 알림만으로 안다. 뒤의 월말 판단: 빠진 날짜 없는 데이터가 필요하다 |
| 사전조건 | 봇이 설치돼 있다 |
| 최소 보장 | 실패한 수집이 무엇인지 기록되고 알림이 간다. 이미 저장된 데이터는 바뀌지 않는다 |
| 성공 보장 | 오늘 시세, 공시, 평가액이 저장됐다. 계좌와 기록이 맞다. 일일 요약이 갔다 |
| 트리거 | 거래일 장 마감 후 정해진 시각 |
| 패키지 | 수집 |
| 포함(include) | [[#UC-S4]], [[#UC-S5]], [[#UC-S7]] |
| 확장점(extension point) | 평가액 기록 뒤: [[#UC-A5]]. 월말이면 끝난 뒤: [[#UC-A2]] |
| 일반화 | — |

**기본 흐름**
1. 스케줄러가 봇을 깨운다
2. 봇이 오늘이 거래일인지 확인한다
3. 봇이 전 종목 일봉과 거래정지 여부를 받아 저장한다
4. 봇이 오늘 접수된 재무 공시를 받아 접수 일시와 함께 저장한다
5. 봇이 계좌를 대조한다
6. 봇이 오늘 평가액과 고점 대비 손실을 기록한다
7. 봇이 일일 요약을 보낸다

**확장**
- **2a. 휴장일이다**
  - 2a1. 봇이 생존 신호만 보내고 끝낸다
- **3a. 시세를 받지 못했다**
  - 3a1. 봇이 재시도한다. 끝내 실패하면 알림을 보내고 4번으로 간다
  - 3a2. 다음 실행 때 빠진 날짜부터 채운다
- **4a. 정정 공시가 있다**
  - 4a1. 봇이 원래 행을 두고 새 행으로 추가한다
- **5a. 계좌와 기록이 다르다**
  - 5a1. 봇이 새 주문을 멈추고 운영자에게 차이를 알린다. 이후는 [[#UC-H6]]

**기본 흐름**
1. 봇이 오늘 종가 시각을 기준 일시로 고정한다
2. 봇이 기준 일시로 시세와 재무를 조회한다
3. 봇이 대상 필터를 적용하고 지정 종목을 뺀다
4. 봇이 종목 점수를 계산한다
5. 봇이 점수 순서대로, 1주 가격이 종목당 예산 이하인 종목을 보유 종목 수만큼 고른다
6. 봇이 판단을 "대기" 상태로 저장한다
7. 봇이 운영자에게 팔 종목과 살 종목을 알린다

**확장**
- **2a. 오늘 시세 수집이 실패한 상태다**
  - 2a1. 봇이 판단하지 않고 알림을 보낸다. 다음 거래일 저녁에 다시 시도한다
- **5a. 하락장 현금 전환이 켜져 있고 코스피가 10개월 평균 아래다**
  - 5a1. 봇이 목표 종목을 비운다
- **5b. 지수 상장지수펀드 비중이 설정돼 있다**
  - 5b1. 봇이 지수 부분의 현재 비중을 계산하고, 허용 범위를 벗어났으면 맞추는 주문을 목표에 넣는다
- **5c. 고를 수 있는 종목이 보유 종목 수보다 적다**
  - 5c1. 봇이 고를 수 있는 만큼만 고르고 나머지는 현금으로 둔다

#### UC-A3 판단 실행

| 항목 | 내용 |
|---|---|
| 범위 | 봇 |
| 수준 | 사용자 목표 |
| 주 액터 | 스케줄러 |
| 이해관계자와 관심사 | 운영자: 같은 주문이 두 번 나가지 않는다. 팔 수 없는 종목 때문에 전체가 막히지 않는다 |
| 사전조건 | "대기" 상태의 판단이 있다. 오늘이 거래일이다 |
| 최소 보장 | 나간 주문은 모두 기록에 있다. 기록에 없는 주문은 나가지 않았다 |
| 성공 보장 | 보유 종목이 목표와 같거나, 다른 이유가 종목별로 기록됐다. 판단이 "완료" 상태다 |
| 트리거 | 거래일 장 시작 전 정해진 시각 |
| 패키지 | 주문 |
| 포함(include) | [[#UC-S3]], [[#UC-S4]], [[#UC-S5]], [[#UC-S6]] |
| 확장점(extension point) | — |
| 일반화 | — |

**기본 흐름**
1. 봇이 "대기" 또는 "실행 중" 판단을 찾는다
2. 봇이 계좌를 대조해 실제 보유 종목을 확인한다
3. 봇이 목표에 없는 보유 종목의 매도 주문 목록을 만든다
4. 봇이 판단을 "실행 중"으로 바꾼다
5. 봇이 매도 주문을 하나씩 보낸다
6. 봇이 매도 체결을 확인하고 종목당 예산을 계산한다
7. 봇이 빈 자리만큼 매수 주문을 점수 순서대로 하나씩 보낸다
8. 봇이 체결 결과와 비용을 기록하고 알린다
9. 봇이 판단을 "완료"로 바꾼다

**확장**
- **3a. 팔 종목이 거래정지다**
  - 3a1. 봇이 그 종목을 "보류"로 기록하고 알린다. 그 자리는 비우지 않는다
  - 3a2. 봇이 이후 거래일마다 재개를 확인하고, 재개된 날 매도 주문을 보낸다
- **5a. 주문 허용 판정이 매수를 막는다 (정지, 손실 한도)**
  - 5a1. 봇이 매도만 실행하고 매수는 건너뛴다. 판단은 "일부 완료"로 남긴다
- **6a. 정해진 시간 안에 체결되지 않았다**
  - 6a1. 봇이 가격을 고쳐 정해진 횟수만큼 다시 보낸다
  - 6a2. 그래도 안 되면 그 종목을 건너뛰고 알린다
- **7a. 현금이 부족하다**
  - 7a1. 봇이 살 수 있는 종목까지만 산다
- **7b. 살 종목이 오늘 거래정지다**
  - 7b1. 봇이 그 종목을 건너뛴다. 다음 순위 종목으로 채우지 않는다

1. 봇이 저장된 상태(모드, 정지 여부, 실행 중 판단)를 읽는다
2. 봇이 증권사에서 오늘 주문 내역과 잔고를 조회한다
3. 봇이 저장해 둔 주문 고유 키와 증권사 주문 내역을 맞춘다
4. 봇이 "보냈는지 모름" 상태의 주문을 "보냄" 또는 "안 보냄"으로 확정한다
5. 봇이 운영자에게 재시작 사실과 확정 결과를 알린다
6. 봇이 평소 스케줄로 돌아간다

**확장**
- **1a. 정지 상태로 저장돼 있다**
  - 1a1. 봇이 정지 상태를 유지한다. 수집과 기록만 한다
- **2a. 증권사에 접속할 수 없다**
  - 2a1. 봇이 주문 없이 재시도만 한다. 접속될 때까지 3번으로 가지 않는다
- **6a. 놓친 스케줄이 있다 (수집, 판단)**
  - 6a1. 봇이 놓친 수집을 채운다. 놓친 판단은 기준 일시를 원래 월말로 두고 실행한다

  - 1b1. 봇이 입출금만큼 고점을 조정한다. 입출금을 손익으로 세지 않는다
- **3a. 이미 "매수 중단" 상태다**
  - 3a1. 봇이 상태를 유지하고, 알림은 하루 한 번만 보낸다

#### UC-A6 월간 성과 보고

| 사전조건 | 지난달 기록이 있다 |

**기본 흐름**
1. 봇이 지난달 수익률, 누적 수익률, 고점 대비 손실, 낸 비용을 계산한다
2. 봇이 같은 기간의 코스피와 전 종목 동일 비중 수익률을 계산한다
3. 봇이 같은 규칙으로 체결 오차 없이 샀다고 가정한 모의 계산값을 구한다

5. 봇이 지표 7개 각각의 최근 12개월 효과를 계산한다
6. 봇이 보고를 저장하고 보낸다

**확장**
- **1a. 지수 상장지수펀드를 들고 있다**
  - 1a1. 봇이 전략 부분과 지수 부분을 따로 계산한다

| 이해관계자와 관심사 | 운영자: 봇이 아무 때나 죽어도 같은 주문이 두 번 나가지 않는다 |
| 사전조건 | 판단 번호, 종목, 방향, 수량이 정해졌다 |
| 최소 보장 | 증권사에 보내기 전에 기록부터 남는다 |
| 성공 보장 | 주문이 "체결", "일부 체결", "취소", "거부" 중 하나로 끝났고 기록됐다 |
| 트리거 | 포함하는 유스케이스의 호출 |
| 패키지 | 주문 |
| 포함(include) | [[#UC-S6]], [[#UC-S7]] |
| 확장점(extension point) | — |
| 일반화 | — |

**기본 흐름**
1. 봇이 판단 번호, 종목, 방향으로 고유 키를 만든다
2. 봇이 같은 키의 주문이 이미 있는지 본다
3. 봇이 주문 허용 여부를 판정한다
4. 봇이 주문을 "보낼 예정"으로 저장한다
5. 봇이 증권사에 주문을 보내고 증권사 주문 번호를 저장한다
6. 봇이 체결을 기다리고 결과를 저장한다

**확장**
- **2a. 같은 키의 주문이 이미 끝났다**
  - 2a1. 봇이 아무것도 하지 않고 그 결과를 돌려준다
- **2b. 같은 키의 주문이 "보낼 예정"인데 증권사 주문 번호가 없다**
  - 2b1. 봇이 증권사 주문 내역에서 같은 종목, 방향, 수량의 오늘 주문을 찾는다. 있으면 그것에 잇고, 없으면 5번으로 간다
- **3a. 허용되지 않는다**
  - 3a1. 봇이 "거부"와 사유를 기록하고 끝낸다
- **5a. 증권사가 주문을 거부했다**
  - 5a1. 봇이 거부 사유를 기록하고 알린다
